## Precedence evidence

Read from the loader implementation at v0.26.19 (`e98a88c9`). The defaults YAML alone does not establish precedence.

1. The shipped defaults file is the base layer and the deployment file is deep-merged on top, so deployment values win.
   - Evidence: `onetimesecret/lib/onetime/config.rb:362-412`
   - Detail: Config.load loads etc/defaults/config.defaults.yaml first, then the resolved environment file, then Enumerables.deep_merge(base, env, preserve_nils: false).
1. At the YAML layer an explicit nil in the deployment file means nil; it does not fall back to the defaults file.
   - Evidence: `onetimesecret/lib/onetime/config.rb:370-373`, `onetimesecret/lib/onetime/utils/enumerables.rb:29-49`
   - Detail: preserve_nils: false selects the branch that lets a nil override win. Enumerables.deep_merge only keeps the base value for a nil override when preserve_nils is true.
1. After the file layers merge, in-code DEFAULTS are merged underneath with nil preservation, so a key that resolves to nil takes the in-code default.
   - Evidence: `onetimesecret/lib/onetime/config.rb:472-485`, `onetimesecret/lib/onetime/config.rb:1629-1660`
   - Detail: after_load calls deep_merge(DEFAULTS, conf); that merger returns the DEFAULTS value when the loaded value is nil. An empty string is truthy in Ruby and therefore replaces the default.
1. Environment variables take effect through ERB inside the YAML files, so an environment read wins over the file literal only for keys whose value is an ERB environment read.
   - Evidence: `onetimesecret/lib/onetime/config.rb:432-445`
   - Detail: load_yaml_with_erb renders the file with ERB and then parses it with YAML.safe_load(permitted_classes: [Symbol, Date, Time], aliases: true). Keys with no ERB span cannot be set from the environment.
1. Passing an explicit path to Config.load skips the defaults layer entirely.
   - Evidence: `onetimesecret/lib/onetime/config.rb:375-403`
   - Detail: base_config is only populated when the path argument was nil (using_default_path); with an explicit path the base layer is {} and the single file is used as-is.
1. File resolution order is test-aware, then etc/<name>.yaml, with the defaults file resolved separately from etc/defaults/<name>.defaults.yaml.
   - Evidence: `onetimesecret/lib/onetime/utils/config_resolver.rb:36-82`
   - Detail: ConfigResolver.resolve checks spec/<name>.test.yaml and apps/**/spec/<name>.test.yaml when RACK_ENV=test, then etc/<name>.yaml. defaults_path checks etc/defaults/<name>.defaults.yaml only.
1. When ConfigResolver finds no main config file, the search falls back to fixed service or utility directories.
   - Evidence: `onetimesecret/lib/onetime/config.rb:36-38`, `onetimesecret/lib/onetime/config.rb:1507-1509`, `onetimesecret/lib/onetime/config.rb:1598-1620`
   - Detail: Config.path falls back to find_configs.first, which searches SERVICE_PATHS (/etc/onetime, ./etc, ./etc/defaults) in service mode and UTILITY_PATHS (~/.onetime first) in CLI mode.
1. There is no environment variable that overrides the configuration file path at this release.
   - Evidence: `onetimesecret/lib/onetime/config.rb:1507-1509`, `onetimesecret/lib/onetime/utils/config_resolver.rb:36-64`
   - Detail: A repository-wide search for ONETIME_CONFIG at v0.26.19 returns no matches. Path selection is RACK_ENV-aware through ConfigResolver.test_environment? and otherwise fixed.
1. Deprecated keys and environment variables are refused by default: the boot policy is strict unless the deployment downgrades it.
   - Evidence: `onetimesecret/lib/onetime/config.rb:200-235`, `onetimesecret/lib/onetime/config.rb:1449-1501`, `onetimesecret/lib/onetime/config.rb:2084-2090`
   - Detail: compatibility.deprecated_config_mode defaults to 'strict' (DEPRECATED_CONFIG_MODE); strict raises OT::ConfigError, 'warn' logs, 'silent' ignores, and an unrecognized value is treated as strict. Entries marked severity: :warn log under both strict and warn.
1. The auth file layers the same way, but its YAML load permits no extra classes.
   - Evidence: `onetimesecret/lib/onetime/auth_config.rb:1119-1146`, `onetimesecret/lib/onetime/auth_config.rb:51-52`
   - Detail: AuthConfig.load_config merges etc/defaults/auth.defaults.yaml under the resolved etc/auth.yaml with preserve_nils: false; load_yaml_from calls YAML.safe_load without permitted_classes, so an unquoted date in the auth file raises where the main file would accept it. A load failure raises ConfigError.
1. The logging file layers the same way through the same resolver.
   - Evidence: `onetimesecret/lib/onetime/initializers/setup_loggers.rb:277-303`
   - Detail: load_logging_config renders both etc/defaults/logging.defaults.yaml and the resolved etc/logging.yaml with ERB, parses each with YAML.safe_load(permitted_classes: [Symbol, Date, Time], aliases: true), and deep-merges with preserve_nils: false.
