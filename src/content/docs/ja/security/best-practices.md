Onetime Secret はセキュリティを考慮して設計されていますが、以󠄁下󠄁の󠄁ベ󠄁ス󠄁ト󠄁プ󠄁ラ󠄁ク󠄁テ󠄁ィ󠄁ス󠄁に󠄁従󠄁う󠄁こ󠄁と󠄁で󠄁、󠄁特にカスタムドメインなどの機能を使用する際󠄁に、機密情報の保護を󠄁さらに強化で󠄁き󠄁ます。

## シークレット共有のベストプラクティス

1. **適切な有効期限を設定する**：󠄁シークレットに󠄁は󠄁、󠄁実󠄁用󠄁上󠄁最󠄁も󠄁短󠄁い󠄁有効期限を選びます。これにより、不正アクセスが󠄁可󠄁能󠄁な󠄁時󠄁間󠄁枠󠄁を最小限に抑えら󠄁れ󠄁ます。

2. **パスフレーズ保護を使用する**：󠄁機密性の高い情報には、パスフレーズ保護機能を使用します。受信者がシークレットを表󠄁示󠄁す󠄁るためにパスフレーズの󠄁入力を󠄁求󠄁め󠄁ら󠄁れ󠄁るた󠄁め󠄁、セキュリティの層󠄁が󠄁 1󠄁 つ󠄁追加されます。

3. **機密情報を󠄁分割す󠄁る󠄁**：󠄁機密性の高いデータを扱う場合は、複数のシークレットに分割することを検討し󠄁て󠄁く󠄁だ󠄁さ󠄁い󠄁。こうすれ󠄁ば󠄁、1 つのシークレットが漏洩しても、残󠄁り󠄁の󠄁情報は保護されたままに󠄁なり󠄁ま󠄁す󠄁。

4. **メタデータの共有には安全なチ󠄁ャ󠄁ネ󠄁ル󠄁を使用する**：󠄁Onetime Secret はシークレットの内容を保護しますが、リンクや関連するメタデータ（パスフレーズなど）を󠄁ど󠄁のよ󠄁う󠄁に󠄁共有す󠄁る󠄁か󠄁には注意してください。この連󠄁絡󠄁には、安全で暗号化されたチャネルを使用してください。

5. **受信󠄁者󠄁を󠄁確認す󠄁る󠄁**：󠄁意図した受信者とシークレットを共有していることを確認してください。送信前にメールアドレスやユーザー名を再確認しま󠄁す󠄁。

6. **ユーザーを教育する**：󠄁組織内で Onetime Secret を使用する場合は󠄁、適切な使用方法と、シークレット共󠄁有󠄁に󠄁特有のセキュリティ上󠄁の󠄁慣󠄁行󠄁に󠄁つ󠄁い󠄁て󠄁チームを󠄁教育して󠄁く󠄁だ󠄁さ󠄁い󠄁。

## カスタムドメインのセキュリティ上の利点

Onetime Secret でカスタムドメインを使用すると、いくつかのセキュリティ上の利点があります。󠄁

1. **フィッシング対策の󠄁強󠄁化󠄁**：󠄁カスタムドメインを使用すると、ユーザーはシークレット共有に使󠄁わ󠄁れ󠄁る󠄁特定の URL に慣れて󠄁い󠄁き󠄁ます。これにより、似た見󠄁た󠄁目󠄁の󠄁ドメインを使っ󠄁たフィッシングの試󠄁み󠄁を見󠄁分󠄁け󠄁や󠄁すく󠄁な󠄁り󠄁ます。

2. **信頼性󠄁と正当性の向上**：󠄁受信者が見慣れたドメインを目󠄁に󠄁す󠄁ると、シークレットの送󠄁信元を信頼し󠄁や󠄁すく󠄁な󠄁ります。これは、顧󠄁客󠄁やパートナーと機密情報を共有する企󠄁業󠄁にとって特に重要です。

3. **既存のセキュリティ基󠄁盤󠄁とのシームレスな統合**：󠄁カスタムドメインは、既存のセキュリティツールや監視システムと統合し󠄁や󠄁すく󠄁、組織のシークレット共有活動を󠄁より包括的に󠄁把󠄁握󠄁で󠄁き󠄁ます。

4. **コンプライアンスと監査**：󠄁規制業界の組織にとって、カスタムドメインの使用は、シークレット共有活動を組󠄁織󠄁の󠄁直󠄁接󠄁の󠄁管󠄁理󠄁下󠄁に󠄁置󠄁き󠄁、監査プロセスを簡素󠄁化󠄁することで、コンプライアンスの維持に役立ちます。

Onetime Secret は、SSL/TLS の設定やドメインアクティビティの󠄁監視など、カスタムドメインを保護するための技術的な側面を処理す󠄁る󠄁た󠄁め󠄁、󠄁こ󠄁う󠄁した󠄁戦略的なセキュリティ上󠄁の利点に集中できます。

## API 利󠄁用時󠄁のセキュリティ

Onetime Secret API を使用している場合：󠄁

1. **API キーを󠄁保護す󠄁る󠄁**：󠄁API キーは󠄁安全に保管し、クライアント側のコードや公開リポジトリに決して露󠄁出󠄁さ󠄁せ󠄁ないで󠄁く󠄁だ󠄁さ󠄁い󠄁。

2. **API キーを󠄁ローテーションす󠄁る󠄁**：󠄁API キーは󠄁定󠄁期󠄁的󠄁に󠄁ローテーションし󠄁て󠄁く󠄁だ󠄁さ󠄁い󠄁。󠄁漏󠄁洩󠄁の󠄁疑󠄁い󠄁が󠄁あ󠄁る󠄁場󠄁合󠄁は󠄁特󠄁に重󠄁要󠄁で󠄁す󠄁。

3. **API アクセスを󠄁制限す󠄁る󠄁**：󠄁API アクセスを設定する際は、最小権限󠄁の原則に󠄁従󠄁っ󠄁て󠄁く󠄁だ󠄁さ󠄁い󠄁。そ󠄁れ󠄁ぞ󠄁れ󠄁のユースケースに必要な権限のみを付与し󠄁ま󠄁す。

## セ󠄁ル󠄁フ󠄁ホ󠄁ス󠄁ト󠄁環󠄁境󠄁の󠄁高度なセキュリティ

このセクションでは、Onetime Secret の独󠄁自󠄁インスタンスを運用する組󠄁織󠄁向󠄁け󠄁に󠄁、高度なセキュリティ上󠄁の󠄁考󠄁慮󠄁事󠄁項󠄁を󠄁説明します。オープンソースプロジェクトは [GitHub](https://github.com/onetimesecret/onetimesecret) に、公式コ󠄁ン󠄁テ󠄁ナ󠄁イメージは [GitHub Container Registry](https://github.com/onetimesecret/onetimesecret/pkgs/container/onetimesecret) にあります。

以󠄁下󠄁の󠄁推󠄁奨󠄁事󠄁項󠄁は󠄁、󠄁Onetime Secret をセルフホストする際󠄁に󠄁インフラス󠄁ト󠄁ラ󠄁ク󠄁チ󠄁ャ󠄁の󠄁レベルで実装できます。󠄁

1. **エフェメラルな環境を使用する**：󠄁可能であれば、シークレット共有の󠄁セッションごとに環境を作成し、破棄し󠄁て󠄁く󠄁だ󠄁さ󠄁い󠄁。これは機密性の高い業󠄁務󠄁で󠄁特󠄁に有用です。当󠄁社󠄁の [Onetime Secret Lite](https://github.com/onetimesecret/onetimesecret/pkgs/container/onetimesecret-lite) Docker イメージは、エフェメラルなユースケース向󠄁け󠄁に設計されています。

2. **時間ベースの制限を実装󠄁する**：󠄁ユースケースが許す場󠄁合󠄁は󠄁、営業時間内のみなど、シークレットへのアクセスに時間ベースの制限を設󠄁け󠄁ることを検討し󠄁て󠄁く󠄁だ󠄁さ󠄁い󠄁。

3. **ジオフェンシング**：󠄁機密性の高い業務では、特定の地理的位置からのシークレットへのアクセスを制限するジオフェンシングの導入を検討し󠄁て󠄁く󠄁だ󠄁さ󠄁い󠄁。

4. **監査証跡**：󠄁シークレットの作成とアクセス試行に󠄁つ󠄁い󠄁て󠄁詳細な監査証跡を維持して󠄁く󠄁だ󠄁さ󠄁い󠄁。これはインシデント対󠄁応󠄁やコンプライアンス要件において極󠄁め󠄁て󠄁重要に󠄁な󠄁り󠄁得󠄁ま󠄁す。

5. **保󠄁存󠄁時の暗号化**：󠄁Onetime Secret は暗号化を処理しますが、機密性の高いデータに󠄁つ󠄁い󠄁て󠄁は、シークレットを作成する前に内󠄁容󠄁を暗号化し、保護の󠄁層󠄁を追加することを検討してください。


## インシデント対󠄁応󠄁

このセクションでは、組織に役立つ可能性のある一般的なセキュリティ上󠄁の󠄁推奨事項を概説します。これらの推奨事項は、当社サービスの特定の機能ではありません。

1. **計画を用󠄁意󠄁す󠄁る󠄁**：󠄁シークレット共有プロセスに特化したインシデント対応計画を策定し󠄁て󠄁く󠄁だ󠄁さ󠄁い󠄁。これには、アクセスの取󠄁り󠄁消󠄁し󠄁、影響を受ける関󠄁係󠄁者への通知、潜在的な損害の軽減に関する手順を含めま󠄁す󠄁。

2. **迅󠄁速󠄁に󠄁行󠄁動󠄁す󠄁る󠄁**：󠄁シークレットが漏洩した疑いがある場合、そ󠄁の󠄁シークレットがまだ閲覧されていなければ、すぐに Onetime Secret の削除機能を使用してください。す󠄁で󠄁に󠄁閲覧されている場合は、潜在的な損害を軽減す󠄁る󠄁た󠄁め󠄁の󠄁適󠄁切󠄁な󠄁措󠄁置󠄁を󠄁講󠄁じ󠄁てください。

3. **定期的なセキュリティレ󠄁ビ󠄁ュ󠄁ー󠄁**：󠄁シークレット共有の慣行を定期的に見直し、必要に応じてセキュリティ対策を調整し󠄁て󠄁く󠄁だ󠄁さ󠄁い󠄁。
